Our approach

Why each piece is built the way it is.

The questions any partner asks — privacy, scale, what runs where — answered component by component: no PHI by default, deterministic safety, and a design that works on low-bandwidth devices. Every choice below serves one rule — help the person, take nothing from them. Honest markers throughout: LIVE = shipped today, DESIGNED = specified, not yet built.

Data model

Local-first. Nothing leaves the device by default. LIVE

The Bridge is a static, self-contained web app (installable as a PWA). All user input — check-ins, journal, the companion conversation — is held in the browser's localStorage on the user's own device. There is no account, no login, no server-side user store, and no telemetry in the live build — which is why "nothing leaves the phone" is literally true right now, not a policy promise.

Reach measurement, when it's switched on DESIGNED

  • A first-party endpoint receives non-identifying counts only — a small set of anonymous funnel events (landed → motivation-check → save-point → resource-viewed → helpline-call-initiated). No names, no free text, no identifiers.
  • Privacy rails ship with the collector: small-cell suppression and no geo×time joins (so a coarse area + an exact timestamp can never re-identify a person in a thin population).
  • Attribution to the county's outcome is done with a spoken "the Bridge sent me" code + a source-of-referral field — never a tracking number. Undercount biases conservative; attribution is a floor.
  • Build sequence: dark in Phase 0 (schema + no-op hooks + synthetic events, zero real telemetry) → live first-party collector at Phase 1.
The companion

Deterministic Safe Mode, with a real crisis override. LIVE

The default companion is a pure, deterministic engine (companion_engine.js) — no network call, no LLM, nothing transmitted. Its behavior is the safety contract:

  • Crisis is never AI-judged. A fixed keyword scan routes any sign of danger to 988 / 911 / the Service Helpline. Deterministic, always.
  • Correction-acceptance + no-repeat labeling. Negation-aware, word-boundary detection: if a user denies a feeling, the engine apologizes, stops, and suppresses that label for the session. It never insists on a rejected interpretation.
  • No diagnosis. Symptom/danger input gets supportive routing to a human — never an assessment, severity call, or dose.
  • Regression-gated. A 22-case test suite (companion_engine.test.js), seeded by real clinical feedback, runs as a commit gate so these guarantees can't silently regress.
The AI

Tiered, with the same guardrails at every level.

  • Tier 0 — Safe Mode LIVE: deterministic + local (above).
  • Tier 1 — on-device AI DESIGNED: Apple Foundation Models on-device in a native build — richer conversation that still never leaves the phone.
  • Tier 2 — cloud assist DESIGNED: explicit opt-in, no PHI, off by default, not used in the pilot.

The invariant across all tiers: the model proposes; the deterministic Safe-Mode layer disposes. Any model output is re-validated — crisis scan on input and output, no-diagnosis/scope lint, correction state honored — before it reaches the user. On any failure it falls back to Tier 0. The worst case is always Tier-0 behavior; the AI can never overrule a safety rule.

Regulatory posture

Wellness/navigation — outside SaMD; Part 2 doesn't attach.

  • FDA: a wellness/navigation tool — it doesn't diagnose, treat, or score — sitting outside Software-as-a-Medical-Device.
  • 42 CFR Part 2: the Bridge creates no SUD record — no identity, nothing transmitted — so Part 2 doesn't attach to it. (Final Rule compliance date for covered programs: Feb 16, 2026; we track it.)
  • HIPAA / PHI: the no-PHI patient lane and any future provider-facing lane are kept architecturally separate. The provider lane is designed Part 2-aware — consent management as a first-class feature — and would run in a dedicated HIPAA environment with a BAA.
Measurement

KCI — anti-extraction by construction.

Key Coherence Indicators score the whole system, not isolated parts, with one defining property: the aggregate cannot rise if any stakeholder (patient, agent, clinician, analyst) is made worse off. In the pilot we honestly instrument ~1.5 axes (patient funnel + a non-PHI helpline aggregate proxy); full multi-axis KCI validation is a Phase-2 claim, stated as such. (Provisional patent filed 2026-03-24.)

Stack & deployment

Boring on purpose. LIVE

  • Static HTML/CSS/JS — no framework, no build step, no database for the patient app. Trivially auditable.
  • Served over HTTPS from a CDN; installable as a PWA (manifest + icons).
  • The internal/partner overview is served behind a real server-side gate (nginx auth on the Coherence Systems site).
